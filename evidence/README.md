# 🖼️ Evidence

> **"Show, don't tell."** Every claim in a case study should be backed by a picture
> of the real thing — a green test run, a coverage report, a pixel diff, a failing
> assertion. This folder is that proof.

Each file is named so a stranger knows what it is **without opening it**:

```
YYYY-MM-DD_Type_Feature_Result.png
```

Examples: `2026-07-21_Unit_ValidateServerName_71-Passed.png` ·
`2026-07-25_Visual_Dashboard_Diff.png` ·
`2026-07-31_Postman_LiveApi_ValidationGap-201.png`

Tidy names show tidy thinking — and that is itself a QA signal.

## How to link an image from a case study

Markdown shows an image with an exclamation mark in front of a link. Inside the
square brackets goes the **alt text** (what the picture shows, for anyone who
can't see it — that's an accessibility habit worth having as a tester):

```markdown
![The unit suite passing: 71 tests, 0 failures](./evidence/2026-07-21_Unit_Validators_71-Passed.png)
```

Because the case studies live in `portfolio/` and the images live in
`portfolio/evidence/`, the path always starts with `./evidence/`.

## Re-capturing anything that's missing

Most of this evidence can be **regenerated in seconds** — you don't need to hunt
for an old screenshot. From `qa-learning/`:

| Want                | Run this                    | Then screenshot                        |
| ------------------- | --------------------------- | -------------------------------------- |
| Green unit run      | `npm run test:unit`         | the terminal summary                   |
| Green integration   | `npm run test:integration`  | the terminal summary                   |
| Coverage            | `npm run coverage`          | the table, and the HTML report page    |
| E2E pass            | `npm run test:e2e`          | the terminal summary                   |
| Visual diff         | see `visual-regression.md`  | the `-diff.png` in `test-results/`     |

The Postman shots (6–9) can't be regenerated by a command — those are pictures of
a real tool doing real work, which is exactly why they're valuable.
